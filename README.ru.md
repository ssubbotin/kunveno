# kunveno

[English](README.md) · Русский · [Español](README.es.md)

Видеовстречи на своём сервере для сети компании: голос, камеры и показ экрана в браузере, с
небольшим сервером на Go, который вы запускаете сами. На эсперанто «kunveno» значит «встреча».

Сделано для офиса или VPN, где звонки нужны без сторонних сервисов: без учётных записей, без
серверов STUN и TURN, без CDN и без аналитики. Комната состоит из названия и PIN; всё работает на
одном хосте за nginx.

## Возможности

- Комнаты с PIN, заданные в конфигурации или созданные на стартовой странице (сохраняются на
  хосте). До 50 человек в комнате (по умолчанию 15).
- Звук от всех, камеры (640x360, 15 кадров/с), один показ экрана за раз.
- Проверка перед входом: выбор микрофона и камеры, индикатор уровня, вход с выключенным
  микрофоном или камерой. Работает на компьютерах без камеры.
- Виртуальный фон, который обрабатывается в браузере: размытие, стеклоблоки, изображения, которые
  администратор кладёт в `backgrounds/`, или своё изображение, которое не покидает браузер.
  Шумоподавление микрофона (стук клавиатуры, посторонние звуки), тоже в браузере.
- Ссылки на комнату (`https://<хост>/join/<комната>#pin=…`), копируются со стартовой страницы
  или из комнаты: получатель попадает на проверку перед входом с выбранной комнатой и
  заполненным PIN. PIN находится во фрагменте адреса, который браузер никуда не отправляет: он не
  попадает ни на сервер, ни в его журналы.
- Индикатор качества связи у каждого участника (потери, время обхода и дрожание задержки,
  измеренные на сервере).
- Эхо-проверка звука в комнате, комнаты с видеофайлом по кругу и комнаты с живой RTSP-камерой.
- Заметки встречи с коммерческим дополнением `kunveno-notes`: речь каждого участника распознаётся на
  сервере, текст последней встречи комнаты можно скачать в Markdown (см.
  [Заметки встречи](#заметки-встречи)).
- Работает в сложных сетях: если у участника не проходит UDP, браузер переключается на ICE по
  TCP на том же порту.
- Интерфейс на русском (по умолчанию), английском и испанском; заголовок установки настраивается.
- Защита от подбора PIN, метрики Prometheus с панелью Grafana, журналы в системном журнале хоста.

## Установка

Нужен сервер на Linux с Docker, доступный вашим пользователям по сети.

**1. Скачайте и распакуйте** комплект:

```bash
curl -fsSL https://github.com/ssubbotin/kunveno/releases/latest/download/kunveno.tgz | tar xz
cd kunveno
```

Этот каталог и есть вся установка:

```
docker-compose.yml
.env            настройки: заполните две строки, остальное по желанию
config.yaml     комнаты, PIN и заголовок; значения по умолчанию работают как есть
data/           комнаты, созданные на стартовой странице, кэш проигрывателя
certs/          сертификат TLS: самоподписанный при первом запуске или ваш
backgrounds/    изображения, которые предлагаются как виртуальный фон
media/          видеофайлы для комнат с проигрывателем
grafana/        источник данных и панель Grafana
```

**2. Заполните две строки в `.env`:**

```bash
PUBLIC_HOST=10.0.0.5            # адрес или имя сервера, как его набирают пользователи в браузере
GRAFANA_ADMIN_PASSWORD=...      # любой надёжный пароль; создать можно так: openssl rand -base64 24
```

**3. Запустите:**

```bash
docker compose pull && docker compose up -d
```

**4. Откройте `https://<PUBLIC_HOST>/`** и войдите в комнату с её PIN из `config.yaml`.
Сертификат самоподписанный, поэтому каждый браузер один раз попросит его принять.

**5. Откройте в межсетевом экране** для пользователей: TCP 443 (сайт) и порт 7000 по UDP и TCP
(звук и видео).

### Повседневные задачи

| Задача | Как |
|---|---|
| Применить изменения в `config.yaml` | `docker compose restart server player` |
| Посмотреть журнал | `journalctl -t kunveno-server -f` |
| Мониторинг | `https://<PUBLIC_HOST>/grafana/`, пользователь `admin`, пароль из `.env` |
| Поставить свой сертификат | заменить `certs/fullchain.pem` и `certs/privkey.pem`, затем `docker compose restart web` |
| Сделать резервную копию | скопировать каталог (`data/` пишет root, поэтому через `sudo`) |

**Обновление** до нового выпуска, в каталоге установки:

```bash
docker compose pull && docker compose up -d
```

Стек работает на образах `latest`, поэтому команда скачивает новый выпуск и перезапускает только
контейнеры, у которых сменился образ; `.env`, `config.yaml` и данные остаются. Чтобы остаться на
одном выпуске, задайте в `.env`, например, `KUNVENO_VERSION=0.2.4`.

### Если что-то не работает

- **Пользователи входят, но ничего не слышат и не видят:** сервер неверно определил адрес для
  звука и видео. Добавьте в `.env` строку `KUNVENO_ADVERTISE_IP=<адрес, по которому к серверу
  приходят пользователи, например адрес в VPN>` и выполните `docker compose up -d`.
- **Порты 80 или 443 заняты:** задайте `HTTP_PORT` и `HTTPS_PORT` в `.env`.
- **Сервер останавливается с сообщением «config.yaml is a directory»:** файл пропал, и Docker
  создал на его месте каталог; удалите каталог, восстановите `config.yaml` из архива и запустите
  снова.

Все настройки `.env` описаны в самом `.env`, все настройки `config.yaml` в разделе
[Конфигурация](#конфигурация). Сертификаты, межсетевой экран, неполадки и пакеты Debian:
[docs/deploy.md](docs/deploy.md) (на английском).

## Администраторам

**Куда идёт трафик.** Весь звук и видео идут через сервер. Это схема SFU (пересылающий сервер):
каждый участник отправляет на сервер по одному потоку на каждый вид (звук, камера, экран), а
сервер рассылает их остальным. Напрямую между участниками ничего не передаётся. Поэтому у каждого
участника исходящий трафик небольшой, а основная нагрузка ложится на канал сервера.

**Шифрование.** DTLS-SRTP на участке «браузер ↔ сервер», то есть по сети всё идёт
зашифрованным. На самом сервере потоки расшифровываются для пересылки, сквозного шифрования между
участниками нет. Сайт и сигнализация идут по HTTPS.

**Трафик.** Ориентиры на одного участника: звук около 40 кбит/с, камера около 350 кбит/с, показ
экрана до 2,5 Мбит/с (`media.share_max_kbps`). На сервер приходит по одному потоку от каждого, а
уходит (участников − 1) копий каждого потока. Для 15 человек с камерами и одним показом экрана это
около 120 Мбит/с исходящего с сервера в худшем случае; встреча того же размера только со звуком
укладывается в 10 Мбит/с.

**Порты.** Всё работает на одном сервере:

| Порт | Назначение |
|---|---|
| TCP 443 | сайт (HTTPS) и сигнализация (WebSocket через nginx) |
| TCP 80 | только перенаправление на 443 |
| UDP 7000 | основной канал звука и видео: один порт на всех участников, новые порты под каждый звонок не открываются |
| TCP 7000 | запасной канал звука и видео для участника, у которого не проходит UDP (обычно NAT или межсетевой экран на шлюзе, обрывающий долгие UDP-потоки); браузер переключается на него сам |

Снаружи больше ничего не нужно: ни STUN, ни TURN, ни внешних сервисов. Внутренние порты сервера
(API, метрики, Prometheus, Grafana, node-exporter) слушают только 127.0.0.1, Grafana открыта через тот же 443 по
пути `/grafana/`.

**Правило для межсетевого экрана.** Разрешить из сетей пользователей к серверу: TCP 443 (и 80),
UDP 7000 и TCP 7000. Если какой-то сегмент сети работает только через TCP 7000, пропуск UDP 7000 из
него даст тем пользователям быстрый канал.

**Показ экрана** встроен в браузер (`getDisplayMedia`), на компьютеры пользователей ничего ставить
не нужно. Работает в Chrome и Firefox на Linux и Windows.

## Заметки встречи

Участник может включить заметки в комнате (Ещё → Вести заметки). Тогда сервис заметок входит в
комнату как участник «Заметки», слушает микрофон каждого человека отдельно и отправляет
распознанные фразы серверу; сервер сохраняет текст: кто, что и когда сказал. В заголовке комнаты у
всех видна отметка «● Идёт запись заметок». Когда заметки выключают или уходит последний человек,
все, кто остался в комнате, видят «Заметки готовы» с кнопкой «Скачать»; на стартовой странице тот
же файл доступен по кнопке «Заметки последней встречи» с PIN комнаты. Файл в формате Markdown:
комната, дата и время, кто говорил и фразы по порядку, с отметками о паузах записи.

- Сервис заметок поставляется как коммерческое дополнение `kunveno-notes` (распознавание речи на
  процессоре сервера, без внешних служб, звук не сохраняется). В этот репозиторий он не входит; о
  лицензии пишите на ssubbotin@gmail.com. Инструкция по установке прилагается к лицензии.
- Без дополнения оставьте `notes.enabled: false` (по умолчанию): в комнатах и на стартовой странице
  заметок не видно.
- Хранятся только заметки последней встречи каждой комнаты, в течение `notes.keep` после того, как
  заметки закончились (выключение или конец встречи; по умолчанию сутки); первая фраза следующей
  встречи заменяет их. Удаление комнаты удаляет и её заметки. Для скачивания нужен PIN комнаты;
  неверные PIN учитываются в той же блокировке, что и при входе.
- Заметки можно удалить раньше срока на стартовой странице: «Заметки последней встречи» →
  «Удалить заметки» с PIN комнаты и подтверждением. Пока идёт запись заметок, удалить их нельзя:
  сначала запись нужно выключить.
- `notes.live: true` показывает фразы в комнате по мере распознавания, в плитке участника
  «Заметки», чтобы проверить качество распознавания.

## Как это устроено

![Как устроен kunveno](docs/images/architecture.svg)

- `kunveno-server` (Go, [pion/webrtc](https://github.com/pion/webrtc)) пересылает потоки (SFU):
  каждый участник отправляет по одному потоку каждого вида (звук, экран, камера), а сервер
  раздаёт их остальным. ICE работает в режиме lite с единственным кандидатом (`media.advertise_ip`),
  один UDP-порт на все медиапотоки и тот же порт по TCP как запасной канал.
- У каждого браузера одно соединение `RTCPeerConnection` с тремя постоянными слотами отправки
  (звук, экран, камера); включение и выключение камеры или показа экрана подменяет дорожку без
  повторного согласования. Предложения SDP всегда делает сервер.
- Веб-клиент (Svelte 5, Vite, TypeScript) собран в статические файлы, которые раздаёт nginx; он
  же завершает TLS и проксирует `/ws` и `/api/` на сервер через loopback.
- `kunveno-echo` и `kunveno-player` входят в комнаты как участники через loopback: эхо по просьбе
  повторяет звук комнаты с задержкой; проигрыватель показывает видеофайл по кругу или живую
  RTSP-камеру на своей плитке камеры (живой поток помечен). Он использует ffmpeg: файл один раз
  перекодируется в VP8 и Opus и кэшируется, поток перекодируется на лету и переподключается каждые
  5 с, если оборвался.

Сертификаты, межсетевой экран, неполадки и вспомогательные сервисы подробно: [docs/deploy.md](docs/deploy.md)
(на английском).

## Разработка

Нужны Go 1.26, Node 22 и ffmpeg для тестов проигрывателя (без него они пропускаются).

```bash
make test        # go vet + go test -race и тесты веб-клиента
make build       # bin/kunveno-server и web/dist
make fmt         # gofmt + go mod tidy

go test ./internal/sfu -run TestCameraFlowsBetweenTwoPeers -v    # один тест Go
cd web && npx vitest run src/lib/pins.test.ts                    # один файл тестов клиента
cd web && npm run check                                          # svelte-check
```

Локальный запуск: скопируйте `deploy/kunveno/config.yaml`, укажите в `media.advertise_ip` адрес
машины в локальной сети (браузеры не собирают кандидатов на loopback, поэтому с `127.0.0.1` звук и
видео не пойдут), запустите `bin/kunveno-server -config <файл>`, затем `cd web && npm run dev`
(Vite проксирует `/ws` и `/api/` на `127.0.0.1:8080`). `go run ./tools/loadgen -n 14 -duration 30s`
добавляет синтетических участников (`-camera <картинка или каталог>` даёт им камеры с
неподвижной картинкой, `-names a,b,c` задаёт имена; нужен ffmpeg). Перед выпуском пройдите ручные проверки из
[docs/test-matrix.md](docs/test-matrix.md).

## Конфигурация

`config.yaml` (читается при запуске; неизвестные ключи сервер отвергает):

| Ключ | Значение |
|---|---|
| `http.listen` | адрес, на который проксирует nginx, на loopback (по умолчанию `KUNVENO_UPSTREAM` из `.env`, иначе `127.0.0.1:8080`) |
| `media.advertise_ip` | адрес, на который браузеры шлют звук и видео (по умолчанию `KUNVENO_ADVERTISE_IP` из `.env`, иначе основной IPv4-адрес хоста) |
| `media.udp_port`, `media.tcp_port` | порты для медиапотоков (по умолчанию 7000; `tcp_port: -1` выключает запасной канал по TCP) |
| `media.share_max_kbps` | потолок битрейта показа экрана |
| `ui.title` | заголовок на стартовой странице и во вкладке браузера |
| `ui.reactions` | эмодзи для реакций участников (1..16; по умолчанию десять) |
| `ui.noise_suppression` | `true` включает шумоподавление (GTCRN) в клиенте тем, кто не выбирал сам (по умолчанию `false`) |
| `rooms[]` | `slug`, `name`, `pin`, `max_participants` и при необходимости `player: {file, name}` для видео по кругу из каталога media или `player: {url, name}` для живой камеры (`rtsp://` или `rtsps://`; учётные данные из адреса скрываются в журналах) |
| `rooms_file` | куда сохраняются комнаты, созданные на стартовой странице (`/var/lib/kunveno/rooms.json`) |
| `backgrounds_dir` | папка с изображениями для виртуального фона (`/var/lib/kunveno/backgrounds`; стек подключает туда `backgrounds/`) |
| `notes.enabled` | `true` включает заметки встречи в комнатах; нужно дополнение `kunveno-notes` (по умолчанию `false`: всё, что связано с заметками, скрыто) |
| `notes.keep` | сколько хранятся заметки после того, как они закончились: целое число и `m`, `h` или `d` (`90m`, `12h`, `1d`, `2d`; по умолчанию `1d`) |
| `notes.live` | `true` показывает фразы в комнате по мере распознавания, для проверки распознавания (по умолчанию `false`) |
| `notes.dir` | где хранятся заметки (`/var/lib/kunveno/notes`, в стеке это `data/notes`) |

`.env` рядом с compose-файлом задаёт выпуск (`KUNVENO_VERSION`), порты, публичное имя хоста для
Grafana и её пароль администратора.

## Эксплуатация

- Журналы: `journalctl -t kunveno-server --since "7 days ago" -o cat` (также `kunveno-web`,
  `kunveno-echo`, `kunveno-player`, `kunveno-prometheus`, `kunveno-grafana`, `kunveno-node-exporter`). Для каждого
  подключения записываются путь медиапотока (UDP или TCP), изменения качества и неверные PIN.
- Метрики: `/metrics` на сервере (только loopback); Grafana по адресу `https://<хост>/grafana/`
  с готовой панелью «kunveno».
- Что хранить на хосте, всё рядом с `docker-compose.yml`: `config.yaml`, `.env`, `data/` (комнаты,
  созданные на стартовой странице, кэш проигрывателя), `certs/` и `media/`.
- RTSP-камера должна быть доступна с хоста; проигрыватель забирает поток по TCP. Пока поток
  недоступен, проигрыватель остаётся в комнате без видео.

## Версии

Выпуски: теги git `vX.Y.Z` на коммитах слияния в `main`; версия видна в подвале стартовой
страницы и в метрике `kunveno_build_info`. Тег публикует образы
`ghcr.io/ssubbotin/kunveno-{server,web,echo,player}` как `X.Y.Z` и `latest` и создаёт выпуск на
GitHub с `kunveno.tgz`: каталогом установки, в `docker-compose.yml` которого зашита эта версия.
`main` публикует `main`, а запрос на слияние из этого репозитория публикует предварительный
`pr-<номер>` (`KUNVENO_VERSION=pr-<номер>` в `.env`, чтобы попробовать его).
